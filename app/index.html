Quick Help

Big Chat tab: orchestrator mode — the Big Model can call the 14 character presets via tools. Supports multiple threads.

Turns tab: batch-run multiple presets from input files. Maintains conversation history across turns.

Chat tab: chat directly with characters that have been messaged. Each character supports multiple threads. Tool calls from Big Chat appear here.

API key & conversations saved in your browser only (localStorage). Requests go straight from your machine to the model provider you route to — OpenRouter by default, plus whichever providers you enable in Settings → Providers (Modal, NVIDIA, Google AI Studio, Groq and the rest of the default list) — and to the web search provider (SearXNG by default, DuckDuckGo as a fallback). No other service receives your keys or conversations.

⚙ API Settings

🌐OpenRouter API Key

The OpenRouter (Free) provider (🧩 Models & Routing → Provider routing) uses this same API key and URL. When the model has a free :free variant it routes to it — e.g. z-ai/glm-5.2 → z-ai/glm-5.2:free — and models OpenRouter prices at $0 (no :free suffix, e.g. stealth/ox-alpha) are served at their base id. Free variants change over time; if the chosen model has no free variant and isn't free by price, the request falls through to the next provider (or shows an error when OpenRouter (Free) is pinned).

🤖 Google AI Studio Key (free-tier detection)

Optional — used only with Google's Gemini API to detect free Google AI Studio endpoints. Models known to have nonzero RPM/TPM/RPD limits are marked from the local catalog; newly listed models are checked with one tiny generateContent probe. A model is marked (free) only when it is in the known nonzero-limit set or its probe succeeds. This includes gemini-2.5-flash, including its google/ and :free model-id variants. Without a key, only the known models can be marked. Use a free-tier key for discovery: a paid key may make paid models pass the probe and can incur usage charges. This never uses OpenRouter's free data. Results are cached for a few hours.

⚡ Modal API Key

Configure Modal.com API accounts (acts as a provider for Moonshot Kimi K3 and future models).
Key Format: wk-<TOKEN_ID>.ws-<TOKEN_SECRET> · Endpoint Format: https://yourusername--kimi-k3-v1-chat-completions.modal.run/v1
Shared endpoints: If your Modal endpoint serves multiple models, use the shared endpoint URL here. The Provider Routing → Models served panel will list every model the endpoint reports via its /models list. Requests send the full OpenRouter model slug (e.g. moonshotai/kimi-k3) as-is.
When the modal(api) provider is routed for a model (e.g. moonshotai/kimi-k3), requests go directly to the first enabled Modal endpoint above with its key, bypassing OpenRouter. Use the plain modal provider instead to have OpenRouter itself route to Modal.

🔁 Repetition loop guard

When the model repeats the same line (while thinking or answering) or the exact same tool call N times in a row, the streaming request is cut off, the repeated copies are removed from the output, and the model is told to continue where it left off. Works during streaming, non-streaming replies, Big Chat, subagents and preset calls.

🎮 Godot engine checking…

godot_run plays a project's own main scene and writes screenshots with Movie Maker mode, so the AI can open a game, run it and look at a frame. Rendering uses the GPU and falls back by itself to a CPU rasterizer (SwiftShader's CPU Vulkan, then Mesa llvmpipe) only when graphics fails or draws nothing; a run that asks for a CPU rasterizer explicitly skips the GPU. Nothing is shown on screen either way — the engine window is parked off-screen for the fraction of a second the run lasts, so a taskbar entry may flash. Renders run offline at a fixed frame rate, not in real time, so a slow machine still produces correct frames. Godot's own --headless mode is a dummy rasterizer that renders nothing, so it is used only for pure-logic tests.

🧠 Project memory

AGENTS.md at the workspace root is auto-loaded into every Big Chat run. The update_memory tool lets the agent read/append to it, so decisions and conventions persist across sessions.

🧰 Skills

Reusable instruction bundles (SKILL.md). Three are built in; add your own at skills/<name>/SKILL.md in the workspace. Enabled skills (name + description) are listed directly in the Big Chat system prompt.

🌐 Web search tool

The web_search tool lets the agent and research subagents query a search engine for live results instead of only fetching known URLs. Provider ranking (below) tries the enabled providers in order, top first; DuckDuckGo is the automatic backup when "Allow fallback" is on. SearXNG is the default (no API key) — point it at your own instance for maximum reliability and privacy. Optional providers such as Tavily, Brave or Mojeek are also supported. The endpoint/key/method fields above still set the legacy single-endpoint default (migrated into the SearXNG provider once). In the desktop app requests go through the main process, so no CORS limits apply.

Provider ranking

Search providers (tried in order) — drag ⋮⋮ to reorder, uncheck to disable, ⓘ to configure

The tool returns ranked results with titles, URLs and snippets. By default it stops there (0) — the agent only sees the search summaries, and fetches full pages on demand (via fetch_url or read: N). Set a number here to make the tool also open the top result pages and include their real text in the answer, so a search for recipes returns actual ingredients and steps. Page-reading is free (it fetches the pages the search already found) and is skipped for pages that block reading; the model can override per call with read: N.

🔗 Fetch tool

The fetch_url tool downloads a page and returns its text so the agent can read any public URL. In the desktop app requests go through the main process, so no CORS limits apply. Response text is capped at 20,000 characters; the wait time below is configurable.

⬇️ Web downloader

The web_download tool saves a real file from the web into the agent's workspace (PDFs, images, archives, anything). In the desktop app it goes through the main process, so no CORS limits apply and redirects are followed. Files land in the workspace and can be viewed with fs_list, moved with fs_move or deleted with fs_delete. The workspace read cap (1000 MB) is well above this download limit, so anything you download here can also be read back or moved. Wait time reuses the Fetch tool timeout.

🖼 Screenshots sent to the model

When a vision-capable model receives tool screenshots (Web Browser tab), the copy sent to the model is downscaled and re-encoded as JPEG to save tokens. The user always sees the full-resolution original in chat.

🌐 Agent browser tools

Gives the agent full control of the Web Browser tab: navigate, click, fill forms, scroll, read pages, screenshot and run page scripts (browser_* tools). The browser is a real Chromium guest sandboxed inside the app (separate process, in-memory cookies) — the user watches every action live in that tab. Available in the installed desktop app only.

Workspace folder In memory

The agent only ever sees paths relative to this folder (e.g. /src/app.js) — never the real location on your PC. It cannot read or write anything outside it, and .. escapes are rejected.

🧰 Default Big Chat tools

The tools enabled by default in every new Big Chat thread. You can still turn items on/off per-thread in that thread's 🧰 Big Chat Capabilities panel, and a tool unchecked here can be re-enabled manually there. Turning this category off starts every new thread with no tools.

Isolated by default: run_webapp serves the app from an isolated local server and opens it in the agent's Web Browser tab, which runs in its own Chromium process and can render in the background — inline pages, multi-file web apps and WebGL/three.js games all run there. There is no host shell.

🧑‍🤝‍🧑 Default Big Chat subagents

Which subagents are available by default when a new Big Chat thread starts (the delegate tool). Unchecked subagents can still be enabled in a thread from its Capabilities panel. Turning this category off starts every new thread with no subagents (without affecting existing threads).

🎭 Default Big Chat presets

Which character presets the Big Model may call by default in a new thread (the call_preset tool). Any preset can be enabled per-thread afterward. Turning this category off starts every new thread with no presets (without affecting existing threads).

🧑🤝🧑 Subagents

The delegate tool spawns isolated worker agents with their own prompts, restricted tools and step budget, keeping their working context out of your main context. Several subagents run in parallel within one turn, capped by "Max parallel sub-agents" — extras are queued and started as slots free up. File-editing tools are serialized per file (and one workspace write at a time), so parallel agents cannot overwrite each other's edits.

Sub-agent profiles

These are the specialists the delegate tool can spawn. Edit the id, name, description, default model, thinking level, memory, system prompt, step budget, allowed tools and which other subagents it may call of each. Each profile's checked tools are granted to that worker; checking profiles under "Can call subagents" lets it delegate to exactly those, nothing else. The global agent-tools master and feature-specific switches (Web Search) remain hard safety gates.
